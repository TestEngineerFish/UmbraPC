# 工作流列表拖拽调序

## 背景

工作流编辑器左侧列表的顺序就是 `wfs` 数组顺序，经 `api.setWorkflows` 落盘。注释已写明「顺序是用户自己排的」，但 UI 尚无调序入口。本需求补上拖拽调序。

参考实现：`src/features/tools/PhrasesTool.tsx`（手柄发起 + 跟手重排 + FLIP）。

## 决策摘要

| 项 | 选择 |
|---|---|
| 拖拽发起 | 仅左侧 grip 手柄 |
| 搜索中 | 禁用拖拽 |
| 撤销栈 | 不进入 ⌘Z（列表级偏好，与画布编辑分开） |
| 实现路径 | 对齐常用语（HTML5 DnD + FLIP），不引入新依赖 |
| 右键菜单 | 不加「上移 / 下移」 |

## 交互

1. 每行左侧增加 `IconGrip` 手柄，`title` 为「拖动调序」。
2. 只有手柄上 `mousedown` 后允许 `dragstart`；点击行仍切换选中，右键仍打开现有 `wfMenu`。
3. `wfQ` 非空（trim 后）时：手柄视觉更淡、`cursor-default`，禁止发起拖拽。
4. 拖拽中：被拖行半透明（对齐常用语 `opacity-45`）；其它行跟手让位，FLIP 补动画。
5. 松手才落盘；无实际位移则不写盘。

## 数据流

- 顺序 = `wfs` 数组下标；不新增 `order` 字段。
- 拖拽中：`setWfs(reorder(...))` + `orderDirty`；**不**调用 `commit()`，不碰 `undoRef` / `redoRef`。
- 松手：若 `orderDirty`，调用 `api.setWorkflows(wfs)`（或 `wfsRef.current`，与松手瞬间状态一致）。
- 防闪烁：越过目标行中线才换位 + FLIP 动画期间锁定（`lockUntil`，时长 `FLIP_MS = 180`）。
- 新建仍追加末尾；`dupWf` 仍插在原条目下方（现有行为不变）。

## 改动范围

- **仅** `src/features/launcher/WorkflowEditor.tsx` 左侧列表区域。
- 行结构：外层改为可拖容器（不能继续整行 `button` 包手柄，避免嵌套交互冲突）；选中点击落在内容区或整行（手柄除外）。
- 复用 `IconGrip`（`src/components/icons.tsx`）；FLIP 参数与常用语一致。
- 不抽取公共 hook；不改主进程 API；不加 npm 依赖。
- 侧栏宽约 200px：手柄约 14px，必要时略收图标方块，保证名称/描述仍可读。

## 验收

1. 无搜索时拖动手柄可改序，松手后重开编辑器顺序保持。
2. 点击选中、右键菜单与拖拽不互相干扰。
3. 有搜索词时无法拖拽调序。
4. 调序列表后 ⌘Z 只影响画布节点编辑，不回滚列表顺序。
5. 拖到列表顶/底稳定，无来回闪烁。

## 非目标

- 过滤视图下的部分重排
- 列表调序进撤销栈
- 右键上移/下移
- 与常用语抽共享 hook
- 键盘调序快捷键
